# CLAUDE.md

Guidance for AI assistants working in this repository.

## What this is

Ocean Snake is a polished, responsive browser snake game. The **entire game is a single
self-contained file, `index.html`** (~4,100 lines) with an inline `<style>` block and one
inline `<script>` — no build step, no framework, no external runtime dependencies. Open it
in a browser and it runs.

Everything else in the repo exists to **package, host, and distribute that one file** across
three deployment targets:

1. **GitHub Pages** — serves the repo root directly as static files (the canonical PWA host).
2. **Sites (Cloudflare Worker)** — a thin [vinext](https://www.npmjs.com/package/vinext)
   (Next.js-compatible) app that redirects `/` → `/game/` and serves the same static PWA.
3. **HTML.cafe** — a PowerShell script that inlines everything into one standalone HTML payload.

The game itself has zero npm dependencies. The npm packages (`next`, `react`, `vite`,
`wrangler`, etc.) exist **only** for the Sites/Worker deployment wrapper.

## Layout

```
index.html              THE GAME — inline CSS + JS, single file, edit this to change gameplay
manifest.webmanifest    PWA install metadata (icons, theme, name)
service-worker.js       Offline cache for the app shell; bump CACHE_NAME when core assets change
assets/                 PNG/ICO logos and PWA icons referenced by the game and manifest

app/                    vinext app-router shell (layout.tsx, page.tsx) — placeholder, NOT the game
worker/index.ts         Cloudflare Worker entry: redirects "/" -> "/game/", else vinext handler
build/sites-vite-plugin.ts   Vite plugin that copies .openai/hosting.json into dist/ at build
scripts/sync-static-game.mjs Copies index.html + manifest + SW + assets into public/game/
tests/sites-package.test.mjs Asserts the built Sites package contains the full static PWA
.openai/hosting.json    Sites hosting config (project id)

deploy-htmlcafe.ps1     PowerShell deploy/build script for HTML.cafe (inlining, WebP, audio opts)
vite.config.ts          Vite config wiring vinext + sites() plugin + Cloudflare plugin
tsconfig.json           Strict TS, ES2022, noEmit (type-check only)

public/game/            GENERATED by sync-static-game.mjs — gitignored, do not commit or edit
dist/, .wrangler/, .next/, node_modules/   Build/tool output — gitignored
```

## Key architectural facts

- **The single source of truth for the game is `index.html`.** `public/game/` is a generated
  copy produced by `scripts/sync-static-game.mjs`. Never edit files under `public/game/` — edit
  the root `index.html` / `manifest.webmanifest` / `service-worker.js` and re-run the sync.
- The Worker (`worker/index.ts`) deliberately redirects the root URL to `/game/` so the static
  PWA's manifest and service worker stay in the top-level browsing context. The `app/` router
  content (`page.tsx` shows "Loading Ocean Snake…") is a placeholder shell, not real UI.
- `sync-static-game.mjs` copies exactly these into `public/game/`: `index.html`,
  `manifest.webmanifest`, `service-worker.js`, and the whole `assets/` directory. If you add a
  new top-level file the game needs at runtime, add it to the `files` array in that script.
- The service worker caches a fixed `CORE_ASSETS` list keyed by `CACHE_NAME`
  (`service-worker.js:1`). **When you change any cached asset, bump `CACHE_NAME`** (e.g.
  `ocean-snake-pwa-v7` → `v8`) so clients pick up the update, and update `CORE_ASSETS` if the
  set of shell assets changed.

## Commands

Requires Node >= 22.13.0 (see `package.json` `engines`). ESM throughout (`"type": "module"`).

```bash
npm install            # install deps (only needed for the Sites/Worker build + tests)
npm run dev            # sync game -> public/game, then vinext dev (local Cloudflare dev server)
npm run build          # sync game, then vinext build -> dist/ (client + server + .openai)
npm run test           # runs `npm run build` then node --test tests/sites-package.test.mjs
npm run start          # vinext start (serve a prior build)
npm run prepare:game   # just the sync step (index.html etc. -> public/game/)
```

There is **no lint step and no standalone type-check script**. `tsc` is configured `noEmit`;
run `npx tsc` manually if you want to type-check the TS files. `npm run test` is the gate for
the Sites deployment — it builds and verifies the packaged PWA is complete.

To just play/iterate on the game with no tooling, open `index.html` directly, or serve the
folder: `python -m http.server 8000` (needed for service-worker/PWA testing, which requires a
secure context — `localhost` counts).

## Inside `index.html` (game code)

All game logic lives in the one inline `<script>` (starts ~line 681). It is plain, framework-free
ES modules-style code operating on a `<canvas id="game">`. Notable patterns:

- Small math helpers near the top: `clamp`, `rnd`, `dist`, `lerp`, `unitFromAngle`.
- Tunable gameplay constants are UPPER_SNAKE_CASE (e.g. `BONUS_MIN_BITES`, `BONUS_MAX_BITES`).
- Persistence via `localStorage` through `readStoredFlag` / `writeStoredFlag` (best score, settings).
- Responsive sizing computed at runtime: `snakeScale`, `headRadius`, `bodyRadius`, `segmentGap`,
  `syncArenaSize`, `scaleWorld` — the arena rescales on resize.
- Synthesized ambient music via Web Audio (`musicConfig`, `createMusicTrack`, `switchMusic`,
  `fadeMusicTo`) used as a fallback; audio suspends/resumes with game state.
- Input is multi-modal: pointer-drag steering, on-screen mobile joystick, WASD/arrow keys,
  Gamepad API (analog/D-pad), and an optional **USB DualSense via WebHID** for raw touchpad
  steering and rumble. WebHID only initializes after an explicit user gesture + browser prompt.
- Haptics use, in order of preference: WebHID DualSense output, the Gamepad haptic actuator,
  then the Vibration API (mobile). Capability-detected; the haptics button hides when unsupported.

When editing gameplay, keep it dependency-free and match the surrounding vanilla-JS idiom.

## Deployment workflow

- **Order matters:** for each release, commit and push the game change first (GitHub Pages
  publishes from the repo), *then* publish that same commit to Sites. See README "Deployment".
- Sites: `npm run test` builds `dist/` and validates the package before you publish through Sites.
- HTML.cafe: `deploy-htmlcafe.ps1` builds a standalone inlined HTML into `dist/` (gitignored).
  Build without uploading: `powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy-htmlcafe.ps1 -NoUpload`.
  It supports `-OptimizeImages` (WebP, needs Python+Pillow), `-OptimizeAudio` (needs ffmpeg),
  and credential flags `-PageId` / `-EditKey` (or `HTMLCAFE_PAGE_ID` / `HTMLCAFE_EDIT_KEY` env vars).

## Conventions & hygiene

- **Never commit secrets.** Deploy keys go in gitignored `.bat`/`.cmd` wrappers or env vars,
  never in tracked files. `.gitignore` excludes `*.bat`, `*.cmd`, `*.url`, `.env*`, `dist/`,
  `node_modules/`, `.next/`, `.wrangler/`, `public/game/`, and `debug.log`.
- The main/default branch is `master`.
- Windows-first environment (PowerShell primary shell). Prefer cross-platform Node scripts for
  build tooling; PowerShell is used for the HTML.cafe deploy path.
- Keep `README.md` (user/deploy-facing) and this file (assistant-facing) in sync when the
  structure, commands, or deploy flow change.
